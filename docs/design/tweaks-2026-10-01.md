# Plan: October tweaks — live SteamCMD output, editor/console keys, CurseForge links
_Round 2 — revised by Claude after Codex rounds 1–2 and owner decisions; the "Round 1 revisions" and "Round 2 revisions" sections overrides anything above it_

## Goal
Five owner-requested tweaks to ArkServerAdmin (a .NET 10 Blazor Server + Radzen app that runs as a
LocalSystem Windows service and manages ARK: Survival Ascended servers for a single admin), cut into
three branches:

1. `fix/steamcmd-live-output` — the Update page's SteamCMD console must stream lines as they happen and
   in true order. Today the banner shows, then nothing until SteamCMD exits, then every line arrives at
   once; SteamCMD's bootstrap lines (`[  0%] Checking for available updates...`) land last.
2. `feat/editor-console-keys` — Ctrl+S saves in the GameUserSettings.ini / Game.ini editors; the RCON
   console input gets command suggestions and a browsable list of common ASA commands; RCON history
   persists per instance across browsers and sessions.
3. `feat/mod-curseforge-links` — mod name and thumbnail in the cluster/instance mod lists link to the
   mod's CurseForge page when it is known.

## Approach

### Branch 1 — live SteamCMD output
Established from the code: `ProcessSteamCmdLauncher`
(`src/ArkAscendedServerAdmin.Infrastructure/Install/SteamCmdProcessLauncher.cs`) starts steamcmd.exe with
stdout/stderr/stdin redirected and `CreateNoWindow`, reading via `OutputDataReceived` /
`ErrorDataReceived`. `SteamCmdRunner` stamps each line on arrival; `ConsolePanel` only coalesces renders
by 90 ms. So the burst is upstream of the app: SteamCMD block-buffers when stdout is a pipe.

1. Prove it in a scratch folder with a throwaway SteamCMD and a small anonymous app: per-line arrival
   times through pipes vs. under a pseudo console. If ConPTY does not stream, stop and report.
2. Add a ConPTY launcher behind the existing `ISteamCmdProcessLauncher` (interface unchanged):
   `CreatePipe`, `CreatePseudoConsole` (512 columns so progress lines never wrap),
   `InitializeProcThreadAttributeList` / `UpdateProcThreadAttribute(PROC_THREAD_ATTRIBUTE_PSEUDOCONSOLE)`,
   `CreateProcessW(EXTENDED_STARTUPINFO_PRESENT)`, SafeHandles throughout.
3. Command line built from `FileName` + `Arguments` with Windows argument quoting.
4. Background reader decodes UTF-8, strips VT sequences (CSI, OSC, single-char escapes), assembles lines
   (`\r\n`/`\n` end a line, bare `\r` overwrites), hands each line to `onOutput`. The stripper/assembler
   is a pure class with unit tests, including chunk boundaries inside an escape sequence.
5. Wait for exit, keep draining while `ClosePseudoConsole` runs, return the real exit code (exit 7 means
   "self-updated, rerun immediately" to the runner).
6. Cancellation kills the process tree as today.
7. If the pseudo console cannot be created, fall back to the existing pipe launcher and emit one line
   saying live output is unavailable.
8. stdout and stderr become one stream; everything goes to `onOutput`. `SteamCmdOutput.TryParseProgress`
   must still match.
9. Existing `SteamCmdRunnerTests` (a `ScriptedLauncher` wrapping the real launcher around `cmd.exe /c
   fake-steamcmd.cmd`) now exercise the ConPTY launcher; add a test that a line echoed before a pause is
   delivered before exit, and one that exit code 7 survives.

### Branch 2 — editor and console keys (no migration)
1. **Ctrl+S.** `Shared/IniEditor.razor` renders one plain `<textarea>` per file; two are in the DOM at
   once. Add a function to the global `wwwroot/js/ark.js` that attaches a keydown listener to one
   textarea, calls `preventDefault()` only for Ctrl/Cmd+S, and invokes a `[JSInvokable]` on the component
   through a `DotNetObjectReference`. The invokable saves only when `!_busy && _dirty && !_conflict`
   (the Save button's own condition) and goes through the same `SaveAsync` path. Dispose listener and
   reference in `DisposeAsync`.
2. **RCON catalog.** A static catalog in Core (name, syntax, description, group) of 20–35 ASA RCON
   commands, each verified against a current reference. Pure filter/rank class (case-insensitive,
   prefix matches first) with unit tests.
3. **Suggestion UI** in `Shared/ConsolePanel.razor` (only when `OnCommand` has a delegate): custom
   absolutely-positioned list under the input; Tab or click accepts; Escape closes; Enter always sends
   the typed text; a button opens the full grouped list. Arrow keys move the highlight only once the
   user has started navigating the list, otherwise they walk history. A per-element JS key filter in
   ark.js prevents the default for handled arrows/Tab.
4. **History file.** Interface in Core, implementation in Infrastructure: plain UTF-8 text in the
   manager's own per-instance folder, one command per line, newest last, cap 200, no consecutive
   duplicates, max 512 chars per line, atomic write (temp + replace) under a per-instance lock, tolerant
   of a missing or hand-edited file. Must not be in backup archives, must survive a world restore, must
   be removed with the instance. `InstancePage` loads it on init / instance change and appends on send
   (including failed sends); `ConsolePanel` stays generic and receives history via parameters.
   Manager-originated commands (probes, schedules, saveworld) are not recorded.

### Branch 3 — CurseForge links (one additive migration)
1. Add nullable `WebsiteUrl` (max 500) to `ModLibraryEntry`; tool-generated migration.
2. `Core/CurseForge/Models/Mods/Mod.cs` already deserializes `Links.WebsiteUrl`. Store it at every
   mapping site (`ModMetadataRefresher`, `ModCommands.UpsertAsync`, `ModSearchHit`) only if it is an
   absolute https URL whose host is curseforge.com or a subdomain; else null. One pure helper, unit-tested.
3. The refresher's change check treats "URL missing or different" as a change so existing rows are
   back-filled on the next refresh, without affecting the changed-since-launch badge (which is about
   `DateModified`).
4. Render name and thumbnail inside `<a target="_blank" rel="noopener noreferrer">` only when the URL is
   set, in all `ModListEditor` row types and on the library page. No guessed URL when it is not set.

## Key decisions & tradeoffs
- **ConPTY over tailing `steamcmd/logs/console_log.txt`.** The log lacks the bootstrap lines, has its
  own timestamp prefix and split lines, and would need de-duplication against the stdout burst. ConPTY
  gives exactly what an interactive console shows. Cost: ~300 lines of P/Invoke and a VT stripper in a
  LocalSystem service.
- **Keep the pipe launcher as a silent-ish fallback** rather than failing the update when ConPTY is
  unavailable.
- **Merge stderr into stdout** (a pseudo console has one output); stderr lines lose their Warning kind.
- **Kill-tree on cancel by pid**, not a job object.
- **Global `window.ark` functions + DotNetObjectReference** instead of introducing ES modules.
- **Custom suggestion list** instead of RadzenAutoComplete or `<datalist>` (needs descriptions and must
  coexist with Enter-to-send and arrow history).
- **History as a text file, not a DB table** (owner's explicit decision); written by the server, so it
  is shared by every browser.
- **Failed sends are recorded in history** so the admin can arrow-up and retry.
- **Store the API's websiteUrl** rather than building a URL from the slug, and whitelist the host.
- **Back-fill through the daily refresher**, no data migration; manual mods stay unlinked.

## Risks / open questions
- ConPTY inside a session-0 LocalSystem service: believed to work (conhost is spawned headless) but not
  exercised by tests; only verifiable on the deployed service.
- ConPTY re-renders output: possible cursor-positioning sequences instead of newlines, duplicated lines
  on repaint, or a final screen flush; the stripper may see sequences beyond CSI/OSC.
- `ClosePseudoConsole` can block until the output pipe is drained on older Windows builds.
- Killing the tree by pid when the child was created with raw `CreateProcessW` (no `Process` object
  owning the handle; pid reuse).
- Does SteamCMD behave differently when it sees a console (interactive prompt, waiting for input, the
  `-- type 'quit' to exit` mode)? `+quit` is passed, stdin handling under ConPTY is undecided.
- GitHub Actions windows-latest must support the ConPTY tests.
- The JSInvokable can arrive after the component is disposed or mid-save; two IniEditors per page.
- History file location relative to backup/restore/delete is not yet confirmed from the layout code.
- Whether the refresher change check and the B8 "changed since launch" badge share state.

## Out of scope
- Ban management, RCON history in the database, per-user preferences, a JS code editor for ini files,
  ES-module refactor of ark.js, changing how the ARK server process itself is launched, deployment.

## Round 1 revisions (override the text above where they differ)

### Branch 1 — status and changes
First pass is implemented (local commit 2faf4f8). Measured with a throwaway SteamCMD: through pipes
everything arrives at 15.4 s; under ConPTY lines stream from 0.04 s and the bootstrap lines arrive
first, before the banner; a 15.5 GB download streamed a progress line every ~2 s; cancel left no
process; all progress lines parse. A finding: the child must be started with `STARTF_USESTDHANDLES`
and null std handles or it inherits the parent's redirected stdout and bypasses the pseudo console.
- Acceptance is **observed terminal order**, evidenced by timestamped real-SteamCMD captures.
- Stripper tests use a captured real SteamCMD frame, chunk sizes 1–7, split UTF-8, bare CR,
  cursor-forward as spaces, flush of a final unterminated line. No early emission of CR-overwritten
  partial lines (SteamCMD's progress lines end in newlines).
- Teardown specified for every path: handle ownership and close order documented; the reader drains
  until the pseudo console is closed regardless of cancellation; an exception from the output callback
  does not stop draining; no retained pipe end blocks EOF. Tests: cancel under heavy output, throwing
  callback.
- Fallback to the pipe launcher also when `CreateProcessW` fails after the pseudo console exists.
- A configuration switch forces the pipe launcher (default: pseudo console), so a misbehaving session-0
  service can be switched back without a redeploy.
- stdin: try closing our write end right after start so behavior matches today (end-of-input instead
  of a hang on an unexpected prompt); keep it only if real SteamCMD still completes correctly.
- LocalSystem/session 0 cannot be exercised from the dev session (blocked by policy). The gate is the
  owner's own alpha service: deploy, run one update, watch; the switch above is the rollback.

### Branch 2 — changes
- Fix the existing lost-edit race in `IniEditor.SaveAsync`: snapshot text and hash before the await,
  record the snapshot as saved, recompute dirty against current text; Ctrl+S during a save is a no-op.
- History never affects sending: send first, record afterwards (success or failure); history I/O
  failures are logged / shown separately and never cause "not sent" or a resend.
- The store is one singleton that rereads, appends, de-duplicates, caps and atomically replaces under
  an app-wide per-instance lock; callers pass only the new command.
- History path comes from the data-root layout type; the store never creates the instance folder; an
  append after deletion is a no-op (or serialized through `IInstanceLocks` if straightforward).
- InstancePage captures the instance id per async operation and discards stale loads; the panel resets
  history position, draft and suggestions when the instance changes.
- File rules: no CR/LF in entries, oversized commands skipped (not truncated), bounded read (tail of
  the file, last 200 valid lines).
- Keyboard state machine: ArrowUp always history. ArrowDown walks history forward while an entry is
  recalled; at the draft with the list open it enters the list; then Up/Down move the highlight (Up
  from the first item returns to the input). Tab accepts the highlighted or top match only when the
  list is open, otherwise normal Tab. Escape closes. Enter sends typed text unless an item was
  explicitly highlighted with arrows, in which case it accepts without sending.

### Branch 3 — owner decision
Keep the migration and the stored `WebsiteUrl`. **No in-app back-fill**: the refresher's change check
stays as on main and simply also writes the validated nullable URL when it updates a row for its usual
reason; adding a mod stores it. Existing rows are back-filled once, out-of-band, by an untracked
PowerShell script (the owner is the only deployment): it reads ids from ModLibrary, calls the
CurseForge API in batches, applies the same https + curseforge.com check, updates only NULL rows in
one transaction, copies the database file first, supports `-WhatIf`, and refuses to run if the column
is missing. Tested against a copy of the dev DB only; the owner runs it on the live DB after deploy.
There is no "manual mods stay unlinked" rule: any row whose id resolves gets a link.
All CurseForge links (new ones and the library page's existing button) open in a new tab.

## Round 2 revisions
- **Branch 1.** Dispose order: when no drain thread exists (start failed), close our read end of the
  output pipe before closing the pseudo console; test an injected start failure completing within a
  deadline and ending in the pipe fallback. Reader failures: expected closure is distinguished from an
  unexpected read error; the latter is logged and announced as one console line ("live output lost,
  update continuing") while the child keeps running and the real exit code is returned.
- **Branch 2.** IniEditor keeps a load-generation counter; a save captures owner, file, generation,
  text and hash and applies its completion effects only if the generation is unchanged. History append
  takes the same per-instance lease as `InstanceDeleteService` (`IInstanceLocks`), only around the file
  write (never across the RCON send), checks the instance folder exists inside the lease, and skips
  recording (debug log) if the lease is not promptly available. Test: append racing delete leaves no
  history or temp file and the delete succeeds.
- **Branch 3 script.** Backup through SQLite's online backup API (the database is in WAL mode), then
  verified (integrity_check, WebsiteUrl column present, same ModLibrary row count) before any write.
  All API calls and validation happen with no transaction open; then one short `BEGIN IMMEDIATE`
  transaction runs `UPDATE ... WHERE Id = @id AND WebsiteUrl IS NULL` per row with a busy timeout, so
  it is safe while the service is running. Tested against a copy with a competing write lock.
