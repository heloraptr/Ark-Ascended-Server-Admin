## Decisions that the plan leaves open

### Core (`ArkAscendedServerAdmin.Core`)
- `Domain/Enums.cs`: `ScheduledActionKind { Restart, RconCommand, DinoWipe }`, `ScheduledActionOutcome { Started, Succeeded, Failed, Skipped, Interrupted }`. Stored as strings, max length 16.
- `Domain/ScheduledAction.cs`: `Id`, `InstanceId?`, `ClusterId?`, `TimeOfDay` (int, minutes since local midnight 0–1439), `Kind`, `Command` (string, empty unless RconCommand, max 512), `WarningMinutes` (int, default 10), `Enabled` (bool, default true). Navigation `Instance?`, `Cluster?`.
- `Domain/ScheduledActionRun.cs`: `Id`, `ScheduledActionId`, `InstanceId`, `LocalDate` (DateOnly), `StartedAt` (DateTimeOffset), `CompletedAt?`, `Outcome`, `Reason` (string, empty when none, max 512). Navigations.
- `Instance.OverridesClusterSchedule` (bool, default false).
- `Scheduling/ScheduleOccurrences.cs` (pure, static, no I/O, no `TimeZoneInfo.Local`; the zone is a parameter):
  - `int EffectiveWarningMinutes(ScheduledAction a)` → 0 for RconCommand, else `WarningMinutes`.
  - `ScheduleOccurrence ForDate(ScheduledAction a, DateOnly localDate, TimeZoneInfo zone)`; `ScheduleOccurrence` is a record with `LocalDate`, `Deadline` (DateTimeOffset?), `Due` (DateTimeOffset?), `SkipReason` (string?). Gap (`zone.IsInvalidTime`) → Deadline/Due null, SkipReason = "The local time HH:mm does not exist on yyyy-MM-dd (clocks moved forward)." Overlap (`zone.IsAmbiguousTime`) → the earlier instant (the larger UTC offset from `GetAmbiguousTimeOffsets`). Due = Deadline − effective warning.
  - `IReadOnlyList<ScheduledAction> Applicable(Instance instance, IEnumerable<ScheduledAction> all)` → the instance's own enabled rows plus, when `!instance.OverridesClusterSchedule && instance.ClusterId is not null`, the cluster's enabled rows; ordered by `Id`.
  - `IReadOnlyList<(ScheduledAction Action, ScheduleOccurrence Occurrence)> DueInMinute(IEnumerable<ScheduledAction> applicable, DateTimeOffset tickMinute, TimeZoneInfo zone)`: `tickMinute` is truncated to the minute; evaluate local dates yesterday/today/tomorrow (relative to `tickMinute` in `zone`) so a warning that crosses midnight still matches; a row matches when `Due` truncated to the minute equals `tickMinute`. Gap occurrences are returned too (with SkipReason) when their *deadline minute* equals the tick minute's local wall-clock — simpler rule: a gap row is reported once, on the tick whose local time equals the first valid minute after the gap (i.e. when `zone.GetUtcOffset` jumps). Keep whatever is simplest to test; the observable requirement is one `Skipped` run row per gap day with the reason.
  - `DateTimeOffset? NextDeadline(IEnumerable<ScheduledAction> applicable, DateTimeOffset now, TimeZoneInfo zone)`: the earliest deadline strictly after `now` over today and tomorrow (skip gaps).
- Unit tests in `test/ArkAscendedServerAdmin.UnitTests/Scheduling/ScheduleOccurrencesTests.cs` with a fixed zone (`TimeZoneInfo.FindSystemTimeZoneById("Eastern Standard Time")`, fall back to "America/New_York" if not found): spring-forward gap 2026-03-08 02:30 → skipped with reason; fall-back overlap 2026-11-01 01:30 → the earlier instant (offset −04:00); warning crossing midnight; RconCommand warning is 0; NextDeadline picks tomorrow when today's is past; Applicable honors `OverridesClusterSchedule` and `Enabled`.
- `Scheduling/IRconOperations.cs` (Core application contract): `Task<CommandResult<string>> ExecuteAsync(int instanceId, string command, CancellationToken ct)` — session-bound: the instance must have a live session; echoes the command and reply to the instance console exactly as `InstanceCommands.SendRconAsync` does today (see backend.md §3b, §3e). Also `IScheduledActionRuns`? No — the runner owns its own DbContext access like `BackupScheduler`.

### Infrastructure / Server
- `AppDbContext`: DbSets `ScheduledActions`, `ScheduledActionRuns`; check constraint `CK_ScheduledActions_SingleOwner` exactly like `CK_IniDocuments_SingleOwner`; enums `.HasConversion<string>().HasMaxLength(16)`; unique index `(ScheduledActionId, InstanceId, LocalDate)`; cascades from Instance and Cluster; `DateOnly` column (SQLite provider maps it). Migration name `ScheduledActions`, generated with the local `dotnet ef` tool from the Server project (see README lines 294–305 for the exact command); run `dotnet ef migrations has-pending-model-changes` after.
- `RconOperations` (Infrastructure or Server, wherever `InstanceCommands.SendRconAsync`'s dependencies live) implements `IRconOperations`; `InstanceCommands.SendRconAsync` keeps its authorization guard and delegates the rest.
- `ScheduledActionRunner : BackgroundService` on the `BackupScheduler` pattern (one-minute tick aligned to the minute, `TimeProvider` for time, `TimeProvider.LocalTimeZone` for the zone, `_inFlight` per instance, scoped DbContext per tick). Startup: set every `Started` row to `Interrupted` (reason "The service was restarted before the action finished."), then prune runs older than 30 days (by `StartedAt`), then tick. Per tick, per instance, rows due in `Id` order:
  1. Insert a run row as the claim. Unique-index violation → already ran today → nothing (no row). Gap occurrence → insert `Skipped` with the gap reason, done.
  2. Preconditions, each writes `Skipped` with a full-sentence reason: instance runtime not `Running` ("The server is not running."); `IMaintenanceGate.IsHeldExclusively` ("An update is in progress."); `_inFlight` has the instance or a second row this minute ("Another action is in progress."); lock `TryAcquire` null (use `InstanceLocks.OperationInProgress` text).
  3. Execute detached (not awaited by the tick), with the instance in `_inFlight`:
     - `Restart` → `IProcessManager.RestartWithCountdownAsync(instanceId, occurrence.Deadline)` (it takes the lock itself — so do **not** hold the lease across it; use `TryAcquire` only as the precondition probe and release it before calling, or check how `RestartWithCountdownAsync` acquires; read backend.md §2c first).
     - `DinoWipe` → hold the lease; countdown to the absolute deadline broadcasting "Wild dinos will be wiped in N minute(s)" (expose a countdown primitive on `IProcessManager`, e.g. `Task BroadcastCountdownAsync(int instanceId, DateTimeOffset deadline, string messageTemplate, CancellationToken ct)`, built from the private `CountdownAsync` loop with the sub-second-slack fix from `ca2fdc9` — do not duplicate the loop), then `IRconOperations.ExecuteAsync(instanceId, RconCommands.DestroyWildDinos)`.
     - `RconCommand` → `IRconOperations.ExecuteAsync(instanceId, action.Command)`.
     - Outcome: `Succeeded` when the operation reports success, else `Failed` with the operation's message as reason; exceptions → `Failed` with the exception message, logged. `CompletedAt` set. Service shutdown while a run is in flight leaves the row `Started` (startup marks it `Interrupted`).
- DI: register the runner and `RconOperations` in the appropriate `Add*` extension (see backend.md §10).
- Facade (`IInstanceCommands` / `IClusterCommands` in Core, implementations in Server/Commands):
  - `Task<CommandResult<IReadOnlyList<ScheduledActionView>>> ListScheduledActionsAsync(int id)` — for an instance: own rows plus inherited cluster rows flagged `Inherited = true` (omitted when `OverridesClusterSchedule`); for a cluster: its rows.
  - `Task<CommandResult> SaveScheduledActionsAsync(int id, IReadOnlyList<ScheduledActionEdit> rows)` — whole-list save: rows with a known `Id` are updated **in place** (EF trap: never delete+re-add), `Id == 0` inserted, rows missing from the list deleted. Validation in `CommandSupport` style, full sentences into `Problems`: TimeOfDay 0–1439, WarningMinutes 0–60, Command required (trimmed, ≤ 512) for RconCommand and cleared for other kinds, an inherited row cannot be saved through the instance facade, ids must belong to the owner.
  - `Task<CommandResult<IReadOnlyList<ScheduledActionRunView>>> ListScheduledActionRunsAsync(int id, int take = 10)` — newest first; for a cluster, runs across member instances.
  - `InstanceEdit.OverridesClusterSchedule` saved by the existing `SaveAsync`.
  - `InstanceSummary.NextDeadline` (DateTimeOffset?) computed with `ScheduleOccurrences.NextDeadline` in whatever builds the dashboard data.
  - `ScheduledActionView`/`ScheduledActionEdit`/`ScheduledActionRunView` records live next to the other facade DTOs in Core.
- Integration tests (`test/ArkAscendedServerAdmin.Infrastructure.IntegrationTests`): runner claims once per day (second tick same minute inserts nothing); seeded `Started` row becomes `Interrupted` at startup; not-running instance → `Skipped` with reason; two rows same minute → second `Skipped` "Another action is in progress."; pruning; facade save/list/delete and validation, in the style of `InstanceCommandsTests`.

## Revision 2 (2026-09-18, evening): cron schedules, own tab, taller history — owner feedback on #44/#45

The owner reviewed the first cut and wants: (1) a cron expression per row instead of a time of day, edited through a builder dialog, with the list showing friendly read-only text and a button that opens the dialog; (2) the schedule on its own tab on the instance page and the cluster page, not on Settings; (3) the history newest first in a virtualized, scrollable box tall enough for about ten rows. Both PRs are unmerged, so they are reworked in place (new commits on the same branches; the migration is regenerated with `migrations remove` + `add`, never hand-edited).

### Schema and Core changes (PR 1, branch `feat/b3-schedules`)
- `ScheduledAction.TimeOfDay` → `Cron` (string, standard five-field expression, max 128, required). Everything else on the row stays (Kind, Command, WarningMinutes, Enabled, owner).
- `ScheduledActionRun.LocalDate` → `ScheduledFor` (DateTimeOffset, the occurrence's deadline instant). Unique index (ScheduledActionId, InstanceId, ScheduledFor): the claim is now once per occurrence, so a row may run several times a day. Keep `StartedAt`, `CompletedAt`, `Outcome`, `Reason`, the (InstanceId, StartedAt) index.
- Migration: remove `20260919004745_ScheduledActions` and add a fresh `ScheduledActions` migration with the new shape; `has-pending-model-changes` clean.
- Cron library: **Cronos** (NuGet `Cronos`, MIT) added through Central Package Management (`dotnet add package` from the Core project; `Directory.Packages.props` gets the version). Friendly text: **CronExpressionDescriptor** (NuGet `CronExpressionDescriptor`, MIT), 24-hour format, used only inside Core's `ScheduleDescriptions.Describe(string cron)` so the UI never references the package; unparsable → the raw expression.
- **DST policy becomes Cronos' policy** (the plan text is updated to match): the zone is `TimeProvider.LocalTimeZone`; an occurrence that falls in the spring-forward gap runs once, right after the transition (a 02:30 job runs at 03:00); a fixed-time job in the fall-back overlap runs once, at the earlier instant; interval expressions (`*/30 * * * *`) run in both hours. No Skipped row for the gap any more. Warning countdown and due instant unchanged: due = deadline − effective warning, matched to the tick minute.
- `ScheduleOccurrences` (Core, pure, still zone-as-parameter): `TryParse(string cron, out CronExpression?)`; `EffectiveWarningMinutes`; `NextDeadline(action, DateTimeOffset after, zone)`; `NextDeadlines(action, after, zone, int count)`; `Applicable` unchanged; `DueInMinute(applicable, tickMinute, zone)` returns the (action, deadline) pairs whose due minute equals the tick minute (compute the next occurrence after `tickMinute + warning − 1 minute` and compare); `NextDeadline(applicable, now, zone)` for the dashboard. `ScheduleOccurrence` becomes `(DateTimeOffset Deadline, DateTimeOffset Due)`.
- Unit tests reworked: parse failures; gap (2026-03-08 02:30 Eastern → 03:00 EDT once); overlap (2026-11-01 01:30 → the −04:00 instant once); an interval expression across the overlap firing twice; several occurrences a day matched once each; NextDeadline; warning crossing midnight.
- Runner: claim keyed by `ScheduledFor`; drop the gap branch; everything else stays. Tests updated accordingly (a row firing twice in a day gets two run rows; the second tick in the same minute still inserts nothing).
- Facade: `ScheduledActionView` gets `Cron`, `Description` (friendly text), and `NextDeadline` (DateTimeOffset?) instead of `TimeOfDay`; `ScheduledActionEdit` gets `Cron`; `ScheduledActionRunView` gets `ScheduledFor` instead of `LocalDate`. Validation: "Row N: the schedule is not a valid cron expression." (Cronos parse failure); "Row N: the schedule repeats faster than its warning countdown." when any two of the next 50 occurrences are closer than the effective warning plus one minute; "Row N: the schedule never runs." when Cronos returns no next occurrence. `ListScheduledActionRunsAsync(id, take)` keeps newest first; the UI will ask for up to 200.
- `docs/.untracked/RELEASE-PLAN-FUTURE.md` § B3 gets a short "Revised 2026-09-18" note at the end of the section stating the cron change, the per-occurrence claim, and the Cronos DST policy (edit the plan file in the main checkout, it is untracked).
